# AGENTS.md — правила работы агента в репозитории StayNest

## Контекст
StayNest — PWA для аренды домов: хозяин создаёт объявление, гость бронирует свободные даты через календарь. Проект — портфолио-кейс, поэтому качество и проверяемость важнее скорости. Полное ТЗ в `docs/TZ.md`, схема БД в `docs/DB.md`, план в `docs/SESSIONS.md`.

## Порядок чтения в начале КАЖДОЙ сессии
1. `CONSTITUTION.md`
2. `AGENTS.md` (этот файл)
3. `docs/TZ.md`
4. `docs/DB.md`
5. `docs/DESIGN.md` (если сессия затрагивает интерфейс)
6. `docs/DECISIONS.md`
7. `docs/LEARNS.md`
8. `docs/TODO.md` и описание текущей сессии в `docs/SESSIONS.md`
9. Навыки из `.opencode/skill/`, которые относятся к задаче (для UI: `design-system`, `pwa-design`, `a11y`)

## Стек (зафиксирован, не менять без записи в DECISIONS.md)
- Монорепо: pnpm workspaces. Node.js LTS, TypeScript в strict-режиме
- API: Fastify, zod (валидация и типы), Kysely + pg, node-pg-migrate (SQL-миграции), pg-boss (фоновые задачи на Postgres), argon2, sharp, S3-клиент для MinIO, web-push, pino
- Web: React + Vite + TypeScript, React Router, TanStack Query, Tailwind CSS, react-hook-form + zod, react-day-picker, i18next (ru/en), vite-plugin-pwa (Workbox)
- БД: PostgreSQL 16 (расширения btree_gist, citext, pg_trgm)
- Хранилище файлов: MinIO (S3-совместимое)
- Тесты: Vitest (unit и интеграционные на реальном Postgres в Docker), Playwright (e2e)
- Прокси и TLS: Caddy. Деплой: Docker Compose на VPS

## Протокол работы в сессии
1. Прочитай документы, затем напиши краткий план из 5–10 пунктов и только после этого пиши код.
2. Работай маленькими шагами. После каждого логического шага: запусти линтер, типы и релевантные тесты.
3. Коммиты: Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `refactor:`), один смысл на коммит. Ветка на сессию: `session/NN-кратко`.
4. Не трогай файлы и модули, не относящиеся к сессии. Если нашёл баг вне рамок, запиши его в `docs/TODO.md` в Backlog.
5. Если ТЗ противоречиво или неполно, выбери самый простой вариант, запиши решение в `docs/DECISIONS.md` и продолжай. Не останавливайся с вопросом, если можно принять разумное допущение. Останавливайся только если решение необратимо или влияет на деньги и безопасность.

## Протокол завершения сессии (обязательно)
1. Запусти полный набор проверок: `pnpm lint && pnpm typecheck && pnpm test` (и e2e, если сессия его затрагивает).
2. Пройди по Definition of Done сессии пункт за пунктом и в итоговом отчёте для каждого напиши "выполнено" или "не выполнено" с причиной.
3. **Ревью:** вызови ревьюверов, назначенных на эту сессию в `docs/SKILLS-AND-AGENTS.md` (раздел 3): `@code-reviewer`, `@security-reviewer`, `@db-reviewer`, `@ui-reviewer`, `@qa-tester`. Исправь все `blocker` и `major`, повтори проверку. Не более двух кругов, остальное в Backlog. Ложные срабатывания запиши в `LEARNS.md`.
4. Обнови `docs/TODO.md`: отметь выполненное, перенеси невыполненное.
5. Допиши в `docs/LEARNS.md`: что оказалось неожиданным, какие грабли, какие команды важны.
6. Допиши в `docs/DECISIONS.md` все новые архитектурные решения (формат ADR).
7. Если менялась схема БД, обнови `docs/DB.md`, чтобы он совпадал с миграциями. Если менялся интерфейс, сохрани скриншоты в `docs/screens/`.
8. Выдай итоговый отчёт: что сделано, вердикты ревьюеров, как проверить руками (команды и URL), что не сделано, что рекомендуется в следующей сессии.

## Соглашения по коду
- Имена таблиц и столбцов: `snake_case`, таблицы во множественном числе, PK всегда `id`, внешние ключи `<сущность>_id`.
- API: префикс `/api/v1`, JSON, ошибки в формате `application/problem+json` с полем `code` (машиночитаемый код, например `booking_dates_unavailable`).
- Даты проживания: тип `date` и `daterange` с границами `[)` (день выезда не занят). Время в `timestamptz` (UTC). Никаких таймзон в датах проживания.
- Деньги: `bigint` в минимальных единицах + `currency char(3)`.
- Валидация входа на каждом эндпоинте через zod. Типы делятся через `packages/shared`.
- Логи: pino, без персональных данных и без токенов.
- Интерфейс: только токены и компоненты из `docs/DESIGN.md`, никаких магических значений, состояния загрузки, пусто, ошибка и офлайн обязательны.
- Фронтенд: компоненты маленькие, состояние сервера только через TanStack Query, фильтры каталога живут в URL (search params).
- Все пользовательские строки через i18n-ключи (ru по умолчанию, en).
