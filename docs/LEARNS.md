# LEARNS: журнал находок и граблей

Агент дописывает записи после каждой сессии в формате: `дата / сессия / что случилось / как решили / что делать в будущем`. Ниже стартовый список известных граблей, чтобы не наступать на них.

## Известные грабли (заранее)
- **iOS и push.** Web Push на iPhone работает только у PWA, добавленного на домашний экран, и запрос разрешения нужен по жесту пользователя. Проверять на реальном устройстве, симулятор не показателен.
- **Service worker и кэш.** Закэшированный `index.html` с устаревшими ссылками на чанки ломает приложение после деплоя. Нужны versioned-ассеты, `skipWaiting` только через баннер обновления, очистка старых кэшей.
- **Календарь и часовые пояса.** Не использовать `new Date('2026-07-10')` для дат проживания (сдвиг в UTC). Работать со строками `YYYY-MM-DD` или с `date-fns` без конвертации во время.
- **daterange нормализация.** Для типа `daterange` Postgres приводит диапазоны к форме `[)`. Не строить диапазон с `'[]'` для дат проживания.
- **EXCLUDE и btree_gist.** Без расширения `btree_gist` ограничение с `listing_id WITH =` не создастся.
- **Нарушение EXCLUDE** возвращает SQLSTATE `23P01`, а не `23505`.
- **SSE за прокси.** Нужны heartbeat и отключённая буферизация, иначе соединение рвётся. В Caddy использовать `flush_interval -1` для маршрута SSE.
- **sharp в Docker.** Использовать образ на glibc (debian/bookworm-slim) или проверить сборку на alpine; следить за версией libvips.
- **Тесты на Postgres.** Параллельный запуск тестовых файлов на одной базе даёт гонки: отдельная схема или база на воркер, либо последовательный запуск интеграционных тестов.
- **Docker обходит UFW.** Порт, опубликованный как `5433:5432`, слушает `0.0.0.0` и доступен извне даже при запрете в UFW. Публиковать только на `127.0.0.1`, а доступ с машины разработчика делать через SSH-туннель (ADR-027).
- **Cookie в dev.** Frontend и API на разных портах: настроить прокси Vite на `/api`, чтобы cookie были same-site.

## Журнал

### 2026-10-20 / Сессия 16 / полировка, тема и демо-данные
- **PowerShell `Get-Content`/`Set-Content` портит кириллицу.** Замена строк через `(Get-Content -Raw) ... | Set-Content -Encoding UTF8` прочитала UTF-8 как ANSI: комментарии и SVG-текст превратились в `Р”РµРјРѕ...`, а собранная OG-картинка показала кракозябры. Для правок с русским текстом использовать `edit`/`write`, а не shell-замены; файлы после массовых правок проверять grep'ом на `Р[Іµѕ]`.
- **Tailwind v4 `@theme inline` требует перезапуска dev-сервера при добавлении нового токена.** Класс `text-on-danger` не появился в CSS после HMR: токен был объявлен позже, чем Tailwind собрал утилиты. Перезапуск `vite` решил проблему; в CI сборка всегда с нуля.
- **`text-white` на `--danger` не работает в тёмной теме.** В светлой коралловый `#C0392B` с белым даёт 5.4:1, в тёмной `#F06A5E` — 3.03:1. Введён `--on-danger` (тёмный текст в тёмной теме); axe поймал это на кнопке удаления в профиле.
- **Axe иногда ложно ругается на контраст до загрузки шрифтов и во время анимации.** Один и тот же профиль то проходил, то давал `color-contrast` на `text-ink-muted`: `animate-page` держит контент полупрозрачным 200 мс. Перед анализом ждать `document.fonts.ready` и окончание анимации (350 мс); в e2e это добавлено в `expectNoA11yViolations`.
- **Тема до первого paint — только внешним скриптом.** CSP в Caddy запрещает inline-script, поэтому выбор темы применяет `public/theme-init.js` до загрузки React; `initTheme()` в `main.tsx` остаётся для синхронизации состояния. Без этого при ручной тёмной теме на светлой ОС мелькал светлый фон.
- **`animate-page` не должен создавать containing block.** `transform` на обёртке страницы ломает `position: fixed` у мобильной панели цены: она уезжает вниз на время анимации. Оставлена только анимация `opacity`; e2e/скриншоты ждут её окончания.
- **Ошибка рендера должна сбрасываться навигацией.** Error boundary, который не реагирует на `location`, оставляет кнопку «На главную» неработающей. Boundary пересоздаётся по `key={pathname}` в `App`.
- **Сид броней хранил рубли как копейки.** `quoteFor` складывал `listing.base` (₽) и писал в `total_minor`, поэтому сводка показывала «319 ₽» вместо «31 900 ₽». Деньги на границе скрипта нужно приводить к минимальным единицам один раз; проверять сумму на экране, а не только факт вставки.
- **Демо-фото 960 px достаточно для карточек, но `lg` не увеличивается.** StockSnap CDN отдаёт только `960w`; `sharp` с `withoutEnlargement` оставляет `lg` равным 960. Для Retina-галереи на десктопе нужны исходники крупнее — записано в Backlog.
- **OG-картинка с кириллицей в SVG.** `sharp`/librsvg корректно рендерит UTF-8, если сам файл действительно UTF-8. После починки кодировки текст «Дома у леса и озера» появился без замены шрифта.
- **SPA не отдаёт OG соцсетям.** Клиентский `useSeo` виден Google (он исполняет JS), но Telegram/VK читают HTML без JS. Поэтому добавлен отдельный HTML-маршрут API `/listings/:id` и Caddy-матчер по `User-Agent`; обычный посетитель по-прежнему получает SPA.
- **`sitemap.xml` и `robots.txt` удобно отдавать API.** Домены и список опубликованных домов уже есть в конфиге/БД; Caddy просто проксирует два пути. В dev те же пути добавлены в `server.proxy` и `preview.proxy`.
- **Фиксированные UUID демо-данных упрощают демонстрацию.** Ссылки на карточки не меняются между перезапусками сида, а фото получают новые UUID-ключи при каждой загрузке. Старые объекты S3 удаляются только после `COMMIT`: иначе откат транзакции оставлял бы строки в БД со ссылками на уже удалённые файлы.
- **Профиль и SSE.** `page.goto(..., { waitUntil: 'networkidle' })` на авторизованных экранах зависает: поток `/me/events` открыт постоянно. В e2e и скриншотах использовать `domcontentloaded` + ожидание заголовка.

### 2026-10-20 / Сессия 15 / PWA, офлайн и Lighthouse
- **Production-сборка несколько сессий собиралась как dev.** `loadEnv(mode, '../..', '')` в `vite.config.ts` читал корневой `.env` с `NODE_ENV=development`; Vite кладёт это значение в `VITE_USER_NODE_ENV` и считает сборку не-production. В `dist` попадали `DevUiPage`, `/dev/ui` и dev-путь `/push-sw.js`, а service worker не регистрировался. Лечение: сохранить `process.env.NODE_ENV` и `VITE_USER_NODE_ENV` до `loadEnv` и восстановить после. Проверять production-сборку по отсутствию `DevUiPage` и наличию `/sw.js`, а не только по зелёному `vite build`.
- **Workbox сериализует `urlPattern` через `toString()`.** Регулярки, вынесенные в `const PRIVATE_API_PATH`, попали в SW как свободные переменные: `ReferenceError` при первом же запросе, runtime-кэши не создавались, ошибка видна только в DevTools SW. Регулярки должны быть литералами внутри функции; e2e на production-сборке это поймал, dev-тесты — нет.
- **`/me` тоже нужно кэшировать для офлайна.** Без него `RequireAuth` при офлайн-reload показывает «ошибка сессии», и избранное/поездки недоступны, даже если их ответы в кэше. `NetworkFirst` для `/api/v1/me` (+ bookings/favorites) и очистка этого кэша при выходе.
- **Невычитанное тело ответа держит запрос открытым.** `refreshSession` возвращал `unauthenticated` на 401/403, не читая body; DevTools показывал `/auth/refresh` pending, Lighthouse не дожидался network idle и падал с «page loaded too slowly». `await response.text()` перед выходом решает проблему.
- **`clientsClaim` + `controllerchange` = reload на первой установке.** Если перезагружать по любому `controllerchange`, первая установка SW вызовет бесконечный/лишний reload. Флаг «обновление запрошено пользователем» (`reloadingRef`) отделяет обновление от первой активации.
- **Очистка при выходе не должна убивать precache.** Удаление всех кэшей делает приложение недоступным офлайн до следующего визита. Удаляем runtime-кэши (`staynest-*`) и IndexedDB, `workbox-precache-*` оставляем; `workbox-expiration` пересоздаётся первым же запросом каталога и не содержит персональных данных.
- **Один logout-хук не покрывает конец сессии.** Кэши надо чистить и при истечении refresh-токена, и после смены пароля, и в других вкладках. Признак «сессия была» — `staynest:session-owner` в localStorage; `endSessionLocally` вызывают logout, смена пароля и `fetchMe` при 401. Между вкладками — `storage`-событие (в текущей вкладке storage не срабатывает, поэтому ещё CustomEvent). Иначе на общем устройстве следующий человек мог увидеть старые поездки офлайн.
- **Отписка push должна идти до logout.** `DELETE /me/push-subscriptions` требует cookie; после `POST /auth/logout` сервер вернёт 401, и строка подписки останется. `useLogout` отписывает устройство до вызова logout, а очистку кэшей делает после.
- **Нельзя очищать QueryClient изнутри queryFn.** Первая версия `fetchMe` при 401 вызывала событие, а слушатель делал `queryClient.clear()` прямо во время выполнения запроса. Запрос завершался в уничтоженный кэш, и `useMe` навсегда оставался `pending` — экран входа крутил скелетон. Теперь `/me` при 401 только чистит SW/IndexedDB и возвращает `null`; QueryClient очищается в `useLogin`/`useLogout`/`useChangePassword`, то есть вне queryFn. Урок: побочные эффекты, меняющие кэш, — только после завершения запроса.
- **Barrel-экспорт `features/catalog/index.ts` тянул календарь на главную.** `HomePage` импортировал `CatalogView` через index, а index реэкспортировал `ListingDetails` → `BookingPanel` → `react-day-picker` (83 КБ JS). Прямой импорт `catalog/components/CatalogView` убрал `booking` и `calendarStyles` из первого экрана: LCP 4.1 → 3.2 с, Performance 79 → 86.
- **Ленивые маршруты и eager-главная — не противоречие.** Профиль, поездки, бронь, хост-разделы и формы вынесены в `app/lazyPages.ts`; главная наоборот статическая, потому что её H1 — LCP-элемент, и цепочка `HomePage → CatalogView → …` добавляла round-trip к LCP. Решение принимать по LCP-элементу, а не по «лениво всё».
- **Английский словарь можно грузить по требованию.** `en` — отдельный чанк 11.7 КБ gzip; `setLocale` стал асинхронным, `useLocale` возвращает `Promise`. Тест профиля пришлось перевести на `await`, иначе он проверял язык до загрузки словаря.
- **`vite preview` не использует `server.proxy`.** Для e2e на production-сборке нужен отдельный `preview.proxy`, иначе `/api` и `/media` возвращают index.html. Порт 4173, отдельный `playwright.pwa.config.ts`.
- **Два service worker — это нормально, если пути разные.** В prod `/sw.js` — Workbox с `importScripts('push-sw.js')`; в dev Workbox выключен, и `/push-sw.js` регистрируется как самостоятельный SW. `PushToggle` выбирает путь по `import.meta.env.DEV`.
- **Lighthouse: `--only-categories=performance,accessibility` в PowerShell приходит одной строкой.** В отчёте `categories: {}`. Проще не передавать `--only-categories` и брать все категории.
- **`vite preview` не сжимает ответы.** Для честного мобильного замера использован локальный статический сервер с gzip и прокси; без gzip FCP завышен. В проде Caddy даёт zstd/gzip и HTTP/2.
- **`'requestIdleCallback' in window` сужает `window` до `never` в else.** TypeScript считает ветку недостижимой, и `window.setTimeout` падает. Проверять `typeof window.requestIdleCallback === 'function'`.
- **SSH-туннель и пароль БД снова разошлись.** `.env` содержал старый пароль staging-Postgres (`28P01`), при этом `staynest:staynest@localhost:5433` работает. Перед сессией проверять подключение, а не только `Test-NetConnection`.

### 2026-10-20 / Сессия 14 / избранное, панель хозяина и профиль
- **Сердечко внутри `<Link>` — невалидный HTML и случайный переход.** Первая версия карточки оставляла ссылку корнем и вешала кнопку поверх. Кнопка внутри `<a>` не только нарушает вложенность интерактивных элементов, но и клик по ней открывает карточку. Карточка перестроена: `div.relative` → ссылка и кнопка-сосед с `absolute`. Заодно `group-hover` для фото остался на обёртке.
- **Сердечко требует `QueryClient` и `ToastProvider` даже в тесте карточки.** `FavoriteButton` использует `useMe`, `useFavoriteIds` и `useToast`, поэтому `ListingCard.test` упал с «No QueryClient set». В тестах презентационных карточек теперь создаётся QueryClient, в него кладётся `queryKeys.me = null`, а карточка оборачивается в ToastProvider. Альтернатива — прокидывать `isFavorite`/`onToggle` пропсами, но тогда состояние снова пришлось бы синхронизировать вручную на каждом экране.
- **`useInfiniteQuery` без явного `pageParam` отдаёт `unknown`.** `fetchFavorites(pageParam)` не компилируется в strict-режиме: параметр страницы выводится как `unknown`. Пришлось явно сузить `pageParam as string | null`; в каталоге это работало из-за вывода из `initialPageParam`, здесь тип потерялся из-за явного дженерика ответа.
- **Профиль без имени — регрессия UX, которую поймал старый тест.** После переноса `h1` на «Профиль» имя осталось только в значении input, и страница перестала показывать, под каким аккаунтом пользователь вошёл. Вернули имя и email в блок аватара (`h2`), а тест теперь проверяет и заголовок страницы, и имя.
- **Хвост навигации: профиль уже есть в шапке.** Пять пунктов нижней навигации в 360 px не помещаются с подписями 14 px. В host-режиме оставили четыре: «Сводка», «Объявления», «Заявки», «Календарь»; профиль доступен через аватар в шапке на любом экране. Это дешевле, чем уменьшать шрифт или прятать подписи.
- **Локальный `DATABASE_URL_TEST` из `.env` может не подходить к docker-базе.** `pnpm test` упал с `28P01`, хотя контейнер healthy. Для прогона задавали `DATABASE_URL_TEST=postgres://staynest:staynest@127.0.0.1:5433/staynest_test` явно. Перед интеграционными тестами проверять пароль через `docker inspect`, а не доверять `.env` (продолжение граблей Сессии 12).
- **E2E-фото через SQL снова дают битые картинки.** E2E вставляет префиксы `e2e/...`, которые не входят в публичную политику бакета. Для скриншотов сгенерировали три WebP через `sharp` и загрузили под `listings/<listingId>/<photoId>/{thumb,md,lg}.webp`, обновив `storage_prefix` только в e2e-базе. В коммит скрипт с тестовыми почтами не попал; e2e-фикстура остаётся прежней (проверяет бронирование, не загрузчик).
- **`max-lines-per-function` добрался до графиков и профиля.** `RevenueChart`, `FavoritesView`, `ProfileAvatar`, `ProfileForm` пришлось разделить: `Bar` как отдельный компонент, `FavoritesGrid`/`OfflineNotice`, хук `useAvatarControls`, схема формы вынесена из тела. Это не косметика: линтер не пропускал функции 61–90 строк.
- **Мок-API разросся до complexity 18.** `authRoute` с PATCH профиля, аватаром и сменой пароля пришлось разделить на `authRoute` и `profileRoute`; иначе ESLint валил тестовую инфраструктуру.
- **Порядок классов Tailwind решает исход, если `cn()` не merge.** Выбранное сердечко красилось `text-danger`, но базовый `text-ink-muted` в собранном CSS шёл позже и перебивал его: на скриншоте залитое сердце оставалось серо-зелёным. Теперь цвет задаётся взаимоисключающей веткой, а не наложением класса. Правило на будущее: не полагаться на порядок в `cn()` для конфликтующих утилит.
- **Занятость «на 30 дней» без числа домов врёт.** Сумма ночей по всем домам при фиксированном знаменателе 30 давала «45 из 30 ночей» и 100% у хозяина с тремя домами. Знаменатель стал `30 × опубликованные дома`; тест с двумя домами фиксирует 4 из 60 и 7%.
- **SVG с `width: 100%` и фиксированным `viewBox` не растягивается.** `preserveAspectRatio` по умолчанию вписывает рисунок по меньшей стороне, и на широкой карточке график оставался 360 px по центру. Для столбцов включили `preserveAspectRatio="none"`, а подписи месяцев и скрытый список вынесли в HTML — иначе текст масштабировался ниже 12 px.
- **Мок PATCH `/me` был мёртвым кодом.** `authRoute` ловил любой запрос, оканчивающийся на `/me`, до `profileRoute`, поэтому тест профиля проверял только тело запроса и тост, но не ответ и обновление кэша. Теперь `/me` матчится только для GET; тест дополнительно смотрит `queryKeys.me` и ошибку 500.
- **Язык менялся в двух местах по-разному.** Переключатель в шапке менял только локаль, а селект в профиле — ещё и `PATCH /me`; письма и push оставались на старом языке. Общий `useLocalePreference` применяет локаль сразу, сохраняет на сервере и откатывает при ошибке.

### 2026-10-20 / Сессия 13 / уведомления, SSE и web push
- **`request.raw.on('close')` убивает SSE сразу после handshake.** В Node `IncomingMessage` считает запрос завершённым, как только тело прочитано, поэтому cleanup подписывался и поток закрывался до первого события. Правильно слушать `reply.raw.on('close')` (ServerResponse) и `request.raw.socket?.on('close')`; тест на реальном HTTP-сервере поймал это сразу, `app.inject` такое не проверяет.
- **SSE: подписка до `hijack`.** Первая версия сначала отправляла `200` и handshake, а затем проверяла лимит потоков. Шестой поток получал «успешный» пустой поток, `429` уже нельзя было отправить, а heartbeat и сокет оставались навсегда. Правильно: `service.openStream` (и его `429`) вызывается до `reply.hijack()`/`writeHead`, а клиент с `close()` регистрируется в hub.
- **`app.close()` висит на hijacked SSE.** Закрытие Map в hub не закрывает `ServerResponse`, поэтому graceful shutdown ждал соединение до таймаута и завершался `exit(1)`. Теперь hub хранит `close()` клиента, `preClose`/`onClose` вызывают `service.close()`, а тот делает `raw.end()`. Тест «открыть поток → app.close за 3 секунды» это фиксирует.
- **`exposeHeadRoute: false` для SSE.** Fastify автоматически вешает HEAD на GET; тот же handler открывал поток, но тело HEAD отбрасывалось — пять HEAD-запросов выключали SSE пользователю. Для `/me/events` HEAD отключён, а `sec-fetch-site: cross-site` отвергается.
- **SSE-тест должен читать блок целиком.** Если сначала ждать `event: notification\n`, строка `id:` остаётся до неё и теряется. Ждать `\n\n` и разбирать весь блок — тогда проверяются и `id:`, и `data:`.
- **`max-lines` и `max-lines-per-function` снова режут модуль.** Сервис уведомлений пришлось разделить на `delivery.ts` (события → запись → push), `mapping.ts`, `service.ts` (HTTP-операции), а SSE-клиент — на `session.ts`, `stream.ts`, `upload.ts`. Это не косметика: без разделения линтер не пропускает файл.
- **Динамический ключ i18n с параметрами требует `defaultValue`.** `t(unionKey, { guest, title })` не проходит типизацию даже при известных ключах; вариант `t(key, { ...params, defaultValue: '' })` компилируется и не меняет поведение, потому что ключ существует. Для описаний всё равно выбрана явная switch-функция с литеральными ключами — читается лучше.
- **VAPID-ключи не обязательны для запуска.** Без них push выключен (`503 push_not_configured`), а in-app и SSE работают. Для ручной проверки пара сгенерирована в локальный `.env` через `pnpm vapid:generate`; в git она не попадает.
- **Локальный Postgres и `.env` могут расходиться по паролю.** `pnpm db:migrate` упал с `28P01`, хотя контейнер здоров; для команд использовали `DATABASE_URL` из `docker inspect`, не меняя `.env`.
- **API и worker — разные процессы с разными event bus.** Если подписать notifications только в API, истечение и завершение брони из worker останутся без in-app уведомлений. Сервис создаётся в обоих процессах; SSE-хаб в worker пуст, поэтому список уведомлений — источник истины, а клиент ещё и опрашивает его раз в минуту.
- **Endpoint push уникален глобально.** При входе второго пользователя в том же браузере подписка перепривязывается через upsert; иначе старый владелец продолжал бы получать push на общий компьютер. `DELETE` при этом фильтруется по `user_id`, чтобы чужую запись нельзя было снять.
- **Caddy буферизует SSE.** Для `/api/v1/me/events` добавлен отдельный `handle` с `flush_interval -1`; без него события приходят пачками или не приходят вовсе.
- **E2E проверяет SSE, а не только запись в БД.** После подтверждения заявки гость видит счётчик в колокольчике без `goto`; это единственный тест, который проходит весь путь `API event → notification row → hub → fetch stream → Query cache`.

### 2026-10-20 / Сессия 12 / бронирование в интерфейсе
- **`request` fixture в Playwright — один cookie-jar на тест.** Сначала вошли хозяином и создали дом, затем тем же контекстом вошли гостем — и дом оказался «своим» для гостя, API вернул `422 booking_own_listing`. Правильно: либо создавать ресурсы до смены пользователя (сделано в тесте), либо держать отдельные `request.newContext()` на роль. Симптом в UI был безобидный: форма осталась на месте, а в `role="alert"` было «Свой дом бронировать нельзя».
- **`tsx watch` под `webServer` не поднимает порт.** С `pnpm -C apps/api dev` Playwright 180 секунд видел `ECONNREFUSED`, хотя вручную сервер стартовал. В e2e-конфиге API запускается как `tsx src/server.ts` без watch; для теста hot-reload не нужен.
- **`getByLabel('Пароль')` находит и кнопку «Показать пароль».** Playwright матчит `aria-label` подстрокой, поэтому нужен `getByLabel('Пароль', { exact: true })` или `getByRole('textbox', { name: 'Пароль' })`.
- **E2E через Vite-прокси удобнее прямого API.** `request.post('/api/v1/...')` наследует `baseURL` (5173), cookies остаются same-origin, а браузер и API видят один origin — не нужны CORS-танцы и `credentials`.
- **Фото для e2e можно не загружать через UI, но нельзя оставлять «битыми» на скриншотах.** В тесте фото вставляются SQL-строками, файлов в S3 нет. Для скриншотов сгенерировали WebP и загрузили в Silo; префикс обязан начинаться с `listings/`, иначе политика бакета не пускает анонимное чтение (в Backlog уже записано, что `*` в политике матчит `/`).
- **Публичный адрес и телефон — это отдельное право, а не поле DTO.** `BookingDetail.contacts` отдаётся только в `confirmed`/`completed`, причём гостю — телефон хозяина, хозяину — гостя. Иначе точный адрес утекал бы через деталь `pending`-брони, которую видит участник.
- **Вкладки «Мои поездки» не совпадают со статусами API.** «Предстоящие» — это `pending`+`confirmed`, а `GET /me/bookings` принимает один `status`. Поэтому список грузится страницами без фильтра и группируется на клиенте; для больших аккаунтов это записано в Backlog (мультистатус).
- **Ключ идемпотентности должен зависеть от тела формы.** Один ключ на компонент ломал бы повтор после изменения дат (`422 idempotency_key_conflict`), а новый ключ на каждый клик ломал бы защиту от двойной отправки. Ключ пересоздаётся только при изменении нормализованного тела.
- **Локальный Postgres в Docker снова быстрее staging-туннеля.** Прогон `booking-concurrency` через SSH-туннель стабильно получал `500` из-за `connectionTimeoutMillis: 2000`: 50 заявок не успевали получить соединение из пула. На локальном `docker compose ... postgres` весь API-набор проходит за 89 секунд. Перед интеграционными тестами поднимать `staynest-dev-postgres-1` и задавать `DATABASE_URL_TEST=postgres://staynest:staynest@127.0.0.1:5433/staynest_test`; не путать с dev-базой.
- **E2E-база готовится отдельной командой.** `pnpm e2e` больше не делает `DROP SCHEMA`: сначала `E2E_DATABASE_URL=... pnpm e2e:prepare`, затем `pnpm e2e`. Так обычный запуск теста не может случайно стереть `staynest_test`/dev-базу, а `globalSetup` подсказывает забытую подготовку. `E2E_DATABASE_URL` должен быть loopback-базой с суффиксом `_test`.
- **Мок-API в web-тестах матчил `/me/bookings` через `endsWith`.** Реальный запрос содержит `?role=guest&limit=50`, поэтому маршрут не срабатывал и список был пустым. Для query-параметров использовать `includes`/разбор URL, а не `endsWith`.
- **Таймлайн нельзя строить по `created_at`.** Порядок событий уже фиксирован по `id` (ADR/LEARNS Сессии 11); UI просто рендерит массив в порядке ответа и дублирует эту гарантию на сервере.
- **`networkMode: 'online'` в TanStack Query даёт вечный скелетон в офлайне.** Если экран открыт впервые без сети, запрос не уходит, `isPending === true`, `isError === false`, и проверка ошибки не срабатывает. Для списков, детали брони и календаря офлайн проверяется **до** `isPending`; иначе пользователь видит бесконечную загрузку вместо «Нет сети». Полноценный офлайн-кэш — С15.
- **Много новых i18n-ключей ломает вывод типа `ReturnType<typeof useTranslation>['t']`.** `ListingPreview.capacityLine` перестал компилироваться с `TS2589: Type instantiation is excessively deep` после роста словаря. Явный `TFunction` из `i18next` решает проблему и не теряет типизацию ключей в остальных местах.
- **Пустую вкладку нельзя закрывать `EmptyState` без пагинации.** С клиентской группировкой первая страница может не содержать нужный статус, а `hasNextPage` остаётся true. Кнопка «Показать ещё» должна рендериться и в пустом состоянии, иначе аккаунт с >50 бронями попадает в тупик.

### 2026-10-19 / Сессия 11 / движок бронирования
- **`FOR UPDATE` на join-запросе обязательно указывать с таблицей.** `.forUpdate()` без аргумента заблокировал бы и `listings`, и `users`, а для `LEFT JOIN` фото Postgres вообще может отказать. `.forUpdate('bookings')` компилируется в `FOR UPDATE OF "bookings"` — проверили через `.compile()`, а не на глаз. Только после этого confirm и cancel действительно сериализуются.
- **Идемпотентность без advisory lock не работает.** Проверка «ключа ещё нет» и вставка брони — две операции; два параллельных одинаковых запроса обе проходят проверку. `pg_advisory_xact_lock(hashtextextended(user_id || ':' || key, 0))` в начале транзакции делает ключ атомарным, а сохранение ответа в той же транзакции гарантирует, что replay увидит готовое тело.
- **Ошибки идемпотентности не сохраняем.** Если бы 409 `booking_dates_unavailable` записывался в `idempotency_keys`, тот же ключ навсегда возвращал бы старый конфликт даже после освобождения дат. Транзакция откатывается, ключ остаётся свободным; успешный ответ сохраняется. Это отличие от «хранить любой ответ» зафиксировано в ADR-063.
- **Лимит pending нельзя считать без блокировки пользователя.** Два параллельных запроса на разные дома могли оба увидеть 4 активные заявки и создать шестую. `SELECT users ... FOR UPDATE` перед подсчётом делает лимит точным между инстансами; блокировка объявления для этого не подходит, потому что дома разные.
- **Порядок блокировок `users → listings → bookings`.** Он совпадает с `availability` (создание блока) и `listings` (публикация/архив). Если поменять местами, возможен дедлок с архивированием объявления, которое тоже читает брони.
- **pg-boss v12 — именованный экспорт.** `import PgBoss from 'pg-boss'` не компилируется: нужен `import { PgBoss } from 'pg-boss'`. `work` принимает batch-массив job'ов, даже если задача одна; `schedule(name, cron, data, { tz, missed: 'once' })`. Схема `pgboss` создаётся при `start()`, её не нужно описывать в миграциях, но нужно помнить про бэкап.
- **`SKIP LOCKED` в джобах.** Истечение и завершение берут строки `FOR UPDATE SKIP LOCKED`: джоб не ждёт confirm и не отбирает у него бронь. Если бы джоб шёл без `SKIP LOCKED`, пачка задач на 100 строк могла бы заблокировать пользовательские запросы.
- **Гонка confirm/cancel имеет две валидные последовательности.** Если confirm успел первым, гость всё ещё может отменить confirmed до заезда — оба ответа 200, финал `cancelled_by_guest`. Если cancel успел первым, confirm получает 409. Поэтому тест проверяет инвариант «нет потерянного обновления», а не конкретного победителя; гонка confirm/decline проверяет ровно одного победителя.
- **`max-lines-per-function` снова режет транзакцию.** Создание брони пришлось разделить на `createInTransaction`, `insertPendingBooking`, `createdResponse`; смену статуса — на `transitionInTransaction`. Это не косметика: ESLint не пропускает функцию на 87 строк.
- **`daterange` сам канонизирует границы.** DB-ревью предположило, что `daterange(..., '[]')` сохранит верхнюю границу включительной и занизит `nights`. На самом деле дискретный `daterange` приводится к `[)`: `'[]'` из `2026-07-10…12` хранится как `[2026-07-10,2026-07-13)`, `'(]'` — как `[2026-07-11,2026-07-13)`. CHECK `half_open_range` для `daterange` всегда истинен; тест теперь проверяет канонизацию, а не мнимый отказ. Ложное срабатывание ревьюера.
- **Истёкшая `pending` всё равно блокирует даты через exclusion constraint.** Фильтр `expires_at > now()` в календаре/каталоге/quote убирает её из выдачи, но `INSERT` новой брони всё равно упрётся в `bookings_no_overlap`, пока строку не перевести в `expired`. Поэтому создание брони под блокировкой объявления сначала истекает просроченные заявки этого дома (с событиями), и только потом считает quote. Иначе при упавшем worker даты «свободны» в UI, но бронь невозможна.
- **Курсор должен проверять реальность даты, а не только regex.** `2026-99-99T99:99:99Z` проходит форму, но `::timestamptz` возвращает `22008` и 500. Валидируем компоненты через `Date.UTC` и ограничиваем год 2000–2100; испорченный курсор даёт 400 `invalid_cursor`.
- **`now()` — время старта транзакции, а не вставки события.** Таймлайн `booking_events` сначала сортировался по `created_at`, и в гонке confirm/cancel последним оказывалось событие, которое на самом деле применилось раньше: транзакция confirm стартовала позже, но взяла блокировку первой. Порядок аудита надо читать по `id` (identity), а `created_at` оставить для отображения. Индекс — `(booking_id, id)`. Это редкий баг, который воспроизводился только под нагрузкой полного прогона.
- **Тесты с БД нельзя запускать двумя процессами параллельно.** Даже при `fileParallelism: false` и advisory lock в `global-setup` два независимых `vitest` на одной тестовой базе дают редкие гонки сброса схемы. Запускать интеграционные файлы последовательно, а конкуренцию проверять внутри одного теста.
- **`INSERT` с `created_at` в `idempotency_keys` работает.** Поле `Generated<Timestamp>` в Kysely допускает явное значение при вставке, поэтому тест очистки может положить старый ключ без `UPDATE` после вставки.
- **50×20 — это быстро.** 1000 HTTP-запросов через `app.inject` с сериализацией на строке объявления проходят за ~13 секунд; отдельный перф-стенд для конкурентности не нужен, но тест помечен большим таймаутом.



### 2026-10-19 / Сессия 9 / цены и календарь
- **`excludeDisabled` в react-day-picker ломает выезд в занятую ночь.** День выезда не занимает ночь, поэтому дата, занятая следующим гостем, должна оставаться кликабельной как конец диапазона. Если пометить её `disabled`, сценарий `[10,12)` + `[12,14)` становится невозможен. Поэтому занятые ночи только стилизуются, а `selectRange` проверяет ночи `[from, clicked)` и при пересечении переносит начало выбора.
- **Клик по занятой дате — это два разных действия.** Как начало диапазона она запрещена, как выезд — разрешена, если все предыдущие ночи свободны. Проверка «занята ли кликнутая дата» должна стоять после определения, начинаем мы диапазон или завершаем; иначе выезд в день заезда соседа блокируется.
- **`today` должен приходить с сервера.** Браузер и сервер могут быть в разных часовых поясах, а «заезд не раньше сегодня» считается по `LISTING_TIME_ZONE`. Календарь отдаёт `today`, клиент по нему отключает прошедшие дни; для запроса окна берётся запас в один день назад.
- **Границы блокировки и брони разные.** В календаре хозяин кликает заезд и выезд, диалог показывает реально блокируемые ночи (`range.to - 1`), а API получает последнюю ночь включительно (`dateTo`). В БД `daterange` полуинтервальный. Ошибка на день видна только в тесте `dateTo = lastNight`; конвертация `+1` спрятана в сервисе и DTO.
- **`Intl.DateTimeFormat` с `timeZone` — дешёвый способ получить «сегодня» без библиотеки.** В тестах проверены `Europe/Moscow` и `UTC` на моменте 22:30 UTC: даты расходятся, поэтому нельзя брать `toISOString().slice(0,10)`.
- **Bigint из Postgres — строка.** `nightly_price_minor` приходит как `string`, как и `base_price_minor`; в DTO и калькулятор он попадает только через `Number()`. Забыть это — получить `"250000"` в JSON и `NaN` в арифметике.
- **Lazy-маршруты в jsdom грузятся дольше секунды.** После выноса каталога, карточки, мастера и календаря в отдельные чанки первый `findByRole` на главной упал по таймауту Testing Library (1 с), хотя приложение работало. `configure({ asyncUtilTimeout: 10_000 })` в setup снимает флап, не пряча реальные ошибки.
- **Динамические ключи i18n.** `t(\`booking.notice.${notice}\`)` не проходит типизацию; для трёх состояний заведён `Record<RangeNotice, TranslationKey>`, заодно исключены опечатки.
- **Чистый калькулятор без `Date` проще тестировать.** Все 33 кейса (високосный год, граница месяца, приоритеты, выходные, min nights, занятость) идут за 20 мс, а сервис остаётся тонким: получить данные из БД, вызвать функцию, преобразовать ошибку в `AppError`.
- **Сезонные правила с одинаковым приоритетом.** Без детерминированного tie-break цена зависела бы от порядка строк в Postgres. Выбрано: приоритет → более поздняя `dateFrom` → меньший `id`; это записано в ADR-056 и покрыто тестом.
- **Окно host-календаря длиннее лимита API.** `today-31 … today+400` — это 431 день, а `calendarQuerySchema` разрешает 400. В тестах это не всплыло, потому что веб-тесты мокают API; ошибку поймал только ручной скриншот живого стенда. Теперь окно `today-31 … today+368` (399 дней). Вывод: сквозная проверка на реальном API обязательна даже при зелёных моках.
- **Блокировка на 8000 лет — это публичный DoS.** `blockInputSchema` сначала не ограничивал длину, а `unavailableNights` разворачивал весь `daterange` в массив до фильтра по окну. Анонимный `GET /calendar` или `/quote` на таком блоке строил миллионы строк. Теперь блок ограничен 366 ночами, причина — 200 символами, `unavailableNights` сначала обрезает диапазон до `[from, to)`, а quote не принимает больше 365 ночей. Урок: любая пользовательская дата-граница должна иметь верхнюю длину до разворота.
- **`max-lines-per-function` и большие экраны.** Календарь и панель цен пришлось разбить на презентационные секции и хуки: `HostCalendarView` — данные, `HostCalendarContent` — раскладка, `HostCalendarSection` — календарь и легенда, `PriceRuleDialog` — форма. Это не косметика: иначе ESLint не пропускает файл.

### 2026-10-19 / Сессия 8 / каталог
- **`ts_rank_cd` возвращает `real`, а `pg` отдаёт его в JS как округлённое число.** Курсор релевантности сравнивал сохранённый JS-ранг `0.1` с `real`-значением `0.10000000149`, поэтому вторая страница была пустой. Приведение к `float8` в SELECT, ORDER BY и WHERE выровняло представление. Это же правило пригодится в Сессии 10 при замерах.
- **Русский стеммер ломает наивные тесты поиска.** Запрос «Костром» совпал с описанием, где есть «место для костра»: оба слова стеммятся к `костр`. Для теста города брать слово, которого нет в общем описании. Проверять не только факт совпадения, но и отсутствие лишних строк.
- **Курсор без `id` нестабилен.** Одинаковая цена или ранг требуют третьего поля в кортеже. Тест с пятью домами по одной цене проходит три страницы и проверяет отсутствие дублей — это дешёвая страховка от регрессии.
- **`mobile: true` в CDP дал пустой скриншот.** При `Emulation.setDeviceMetricsOverride` с `mobile: true` Edge в headless снял белое полотно. Рабочий вариант: `mobile: false` и ширина 360 — медиазапросы срабатывают по ширине, снимок корректный.
- **Первый экран 360 px был перегружен.** Заголовок, подзаголовок и форма в один столбец занимали всю высоту, карточки начинались ниже сгиба. На мобильном убрали подзаголовок и eyebrow, форму сжали в две колонки (поиск и город на всю ширину, гости и кнопка рядом). Скриншот после правки показывает фильтры и начало выдачи.
- **Lighthouse через `pnpm dlx` и Edge.** `pnpm dlx lighthouse@12.8.2 --chrome-path=...\msedge.exe --chrome-flags="--headless=new"` работает без установки в проект и без Chrome. Категория Accessibility дала 100 на каталоге и карточке. Единственное замечание — `label-content-name-mismatch` у кнопки языка: `aria-label` не содержал видимого «RU». Доступное имя теперь включает локаль.
- **Публичный DTO отдельно от owner-DTO.** Соблазн переиспользовать `ListingDto` из Сессии 5 велик, но он тянет `addressLine`, точные координаты и `pendingBookingsCount`. Отдельные схемы в `packages/shared/src/catalog.ts` и тест на отсутствие приватных ключей дешевле, чем надеяться на дисциплину.
- **Ревью поймало ошибку единиц цены.** В URL и API цена хранится в копейках, а поле фильтра подписано рублями. Первая версия отправляла введённые рубли как копейки: «до 10 000 ₽» превращалось в «до 100 ₽» и давало пустую выдачу. Теперь конвертация через `minorToInput`/`inputToMinor`, а компонентный тест проверяет и отображение URL `priceMax=750000` как «7500», и запрос `priceMax=800000` после ввода «8000». Тесты фильтров проверяли только сериализацию уже готовых копеек и потому молчали.
- **Контракт ТЗ и внутренние имена разошлись.** ТЗ просит `price_min`, `price_max`, `bedrooms_min`, `type[]`, `amenities[]`, а web пишет camelCase. API теперь принимает оба варианта и дедуплицирует массивы; иначе внешний клиент по ТЗ получал бы 200 и всю выдачу без фильтра.
- **Курсор и фильтры должны сверяться.** Если q изменился, а курсор остался, сервер теперь отвечает `400 invalid_cursor`: иначе граница страницы считалась бы по старому запросу, а фильтр — по новому.
- **`toISOString()` теряет микросекунды Postgres.** Курсор `newest` хранил время с миллисекундами, а `now()` в сидах пишет микросекунды: вторая страница начиналась после усечённой границы и строки пропадали. Теперь время в курсоре — `to_char(... 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`, а тест вставляет три значения с разными микросекундами и проходит все страницы.
- **Мобильная цена должна быть видна сразу.** Блок цены внизу статьи на 360 px не виден. Добавлена фиксированная панель над нижней навигацией, а на десктопе цена переехала в правую колонку рядом с галереей.
- **Мозаика галереи не должна оставлять дырки.** При 3–4 фото сетка 4×2 оставляла пустые ячейки. Раскладка теперь зависит от числа фото: большое слева, остальные стопкой справа.
- **dev-данные для скриншотов.** В dev-базе было два опубликованных дома; для проверки сетки временно продублировали объявления с теми же файлами в Silo. Демо-фото и полноценный сид — Сессия 16, в коммит временные данные не попали.
- **Полный web-прогон стал флапать по таймауту.** Тест мастера в jsdom занимает ~4.2 с при дефолтных 5 с; после роста `App.test` параллельный прогон начал стабильно его ронять. Подняли `testTimeout`/`hookTimeout` до 15 с в `apps/web/vite.config.ts` и проверили два полных прогона подряд. Снижать время самого теста (fake timers для autosave) — отдельная задача, не повод держать красный DoD.

### 2026-10-19 / Сессия 7 / мастер объявления
- **Сводка ошибок перехватывала фокус на каждом исправлении.** `ListingIssuesAlert` фокусировалась на любом изменении списка ошибок. Пользователь набирал название, первый символ убирал ошибку поля, alert снова забирал фокус, и остальные символы уходили в никуда. Тест поймал это как «в поле осталась одна буква». Теперь сводка фокусируется только при переходе «ошибок не было → появились»; повторная отправка с другой ошибкой не обязана перехватывать фокус, потому что рядом есть ссылки на поля.
- **localStorage спасает быстрее, чем debounce.** Автосохранение ждёт 900 мс, поэтому закрытие вкладки сразу после ввода потеряло бы последние символы. Снимок пишется на каждое изменение синхронно и хранит шаг, время серверной версии и `dirty`. При открытии мастер сначала смотрит на снимок, потом на сервер.
- **Конфликт версий без `If-Match`.** Сравниваем `updatedAt` сервера с `baseUpdatedAt` снимка с допуском 1 секунда. Если сервер новее — показываем выбор; иначе восстанавливаем свои правки. Это не заменяет optimistic locking для API, но закрывает сценарий «две вкладки» в MVP без изменения контракта.
- **Снимок нельзя перезаписывать, пока конфликт не разрешён.** Эффект автосохранения на монтировании писал серверную форму и затирал локальный снимок до нажатия «Вернуть мои правки». Добавили `snapshotPaused`: пока конфликт открыт, localStorage не трогаем.
- **Подписи пяти шагов не влезают в 360 px.** Flex-элементы с `min-w-0` сжались до одной буквы. На мобильном оставили номера и галочки, полное имя — в `aria-label`; текущий шаг назван над прогресс-баром.
- **`scrollIntoView` прячет заголовок под sticky-шапкой.** После перехода на следующий шаг h1 оказывался под шапкой. Добавили `scroll-mt-24` на корень мастера.
- **Проверка 360 px через iframe снова пригодилась.** Браузерный инструмент не даёт emulation viewport, поэтому временный `public/mobile-check.html` с iframe нужной ширины показывает настоящие медиазапросы и cookie-сессию. После снимков файл удаляется.
- **Публикация из мастера не должна ждать autosave-таймер.** `persist()` встаёт в ту же цепочку промисов, что и автосохранение, и отправляет самую свежую форму; иначе publish мог уйти со старыми полями.
- **Фоновое автосохранение не должно двигать фокус.** Второй круг ревью нашёл регрессию: баннер ошибки сохранения фокусировался и прокручивал страницу при каждом сбое PATCH, выбивая курсор из поля. Теперь ошибки автосохранения показываются тостом (`role="alert"`), а фокус перехватывает только явное действие пользователя — публикация, архив или ручное сохранение.
- **Публикация по Enter опасна на последнем шаге.** Форма с полями цены и правил отправлялась по Enter и запускала публикацию. Оставили Enter = «Далее» на шагах 1–4; на шаге предпросмотра публикует только кнопка, плюс `inFlight`-защита от двойного клика.
- **Незаконченный черновик должен удаляться с любого шага.** Кнопка удаления раньше была только на последнем шаге, а до него нельзя дойти без заполнения всех полей и трёх фото. Перенесли блок удаления во все шаги; подтверждение осталось.
- **Конфликт должен блокировать поля, а не молча терять ввод.** Пока пользователь не выбрал серверную версию или свои правки, `fieldset` и кнопки сохранения/публикации/удаления недоступны. Иначе ввод уходил в состояние, которое не писалось в localStorage из-за `snapshotPaused`.

### 2026-10-19 / Сессия 5 / объявления
- **Черновик и `NOT NULL`.** Схема Сессии 2 требовала `title`, `city`, `max_guests`, `bedrooms`, `beds`, `base_price_minor`; пустой черновик создать было нельзя. Снимать ограничения глобально опасно: сняли `NOT NULL`, но добавили CHECK `listings_complete_when_not_draft`. Откат миграции удаляет недозаполненные черновики — заполнить их вымышленными данными было бы хуже. См. ADR-042.
- **HTML-валидация молча блокирует submit.** У `NumberField` был `max=99` по умолчанию; цена 7500 не проходила constraint validation, `button.click()` не порождал ни submit-события, ни JS-ошибки, ни запроса. Отладка: навесить capture-листенер на `submit` и проверить `form.checkValidity()`. Вывод: не задавать `max` там, где верхняя граница серверная, и проверять валидность формы после ручного ввода.
- **`ON CONFLICT` и deferrable unique.** `listing_photos_position_uq` объявлен `DEFERRABLE INITIALLY DEFERRED`, а Postgres не принимает его арбитром `ON CONFLICT` (`55000`). Для сидов фото сначала удалять строки, потом вставлять.
- **`it.each` выводит тип строки из литерала.** Массив с опциональным `payload` дал `{} | null | undefined`, и `app.inject` перестал типизироваться. Параметризованный колбэк нужно явно типизировать объектом теста (`attack: Attack`).
- **Скриншоты и fixed-навигация.** При `captureBeyondViewport` нижняя навигация рисуется на высоте первого экрана и накрывает поля. Для полностраничного снимка переводим `nav.fixed` в `position: static` на время кадра; навигация оказывается в конце документа.
- **Словари i18n и `max-lines`.** `ru.ts` и `en.ts` переросли 300 строк. Дробить плоский словарь не стали: добавили `eslint-disable max-lines` с объяснением, чтобы порядок ключей оставался синхронным.
- **Публикация без загрузчика фото.** В Сессии 5 UI не умеет загружать фото, поэтому публикация из интерфейса всегда упирается в `photos_too_few`. Это ожидаемо до Сессии 6; ошибка показывается списком со ссылками на поля, а ручная проверка успешной публикации делается после вставки фото в БД.
- **Ошибка публикации — не тост.** При `422 listing_incomplete` тост дублировал список полей и перекрывал его. Теперь при наличии `errors[]` показываем только сводку, тост — для остальных ошибок.
- **Длины JS и PostgreSQL расходятся.** Серверная проверка использовала `.length` (UTF-16 code units), а `char_length` в PostgreSQL — code points. Описание из emoji проходило проверку сервиса, но нарушало CHECK в БД → 500. Ввели `textLength` и используем её в zod, сервисе и форме; SQLSTATE `23514` дополнительно превращаем в 422. См. ADR-046.
- **Валюта из API роняла список.** `Intl.NumberFormat` бросает `RangeError` на `currency: '123'`, а `currency` принимал любые три символа. Ограничили MVP до `RUB`, добавили try/catch в `formatMoney`, чтобы старые/битые данные не давали белый экран.
- **TOCTOU при смене статуса.** Проверка «нет активных броней» и `UPDATE` были разными запросами. Перенесли чтение, проверки и запись в одну транзакцию с `FOR UPDATE`; два параллельных publish теперь дают 200 и 409. См. ADR-045.
- **Кэш `/me/listings` был безымянным.** Ключ `['listings','mine']` переживал смену пользователя в той же вкладке до refetch. Добавили id пользователя в ключ и `enabled` по `useMe`.
- **Host-маршрут и режим.** Прямой заход на `/host/listings` оставлял режим «Я ищу» и гостевую навигацию. AppLayout теперь запоминает вход в host-маршрут и один раз переключает режим, а нижнюю навигацию выбирает ещё и по пути.
- **`aria-label` на карточке прячет содержимое.** Ссылка-карточка с `aria-label` теряла статус, цену и число заявок в доступном имени. Убрали label: содержимое карточки само даёт понятное имя.
- **Ошибка PATCH — тоже сводка.** При `422 listing_incomplete` от PATCH показывали общий тост. Теперь `errors[]` маппятся на поля формы, сводка получает фокус; `basePriceMinor` переводится в якорь `basePrice`.
- **`noValidate` и серверная валидация.** После фикса `max` осталась нативная валидация, которая блокирует submit без сообщений приложения. Форма редактора теперь `noValidate`, а границы проверяет общий код/сервер.
- **Refetch не должен затирать ввод.** Форма сбрасывалась эффектом на каждое новое значение `listing` из React Query, включая фоновый refetch после сохранения/реконнекта. Теперь сброс только при смене `listing.id`; данные после сохранения и так совпадают с формой.
- **`aria-describedby` на несуществующий hint.** `FieldShell` всегда включал `hintId`, даже когда вместо подсказки рендерится ошибка. Исправили: при ошибке ссылка только на `errorId` (заметил QA-ревьюер).

### 2026-10-19 / Сессия 4 / каркас web
- **Origin-guard и 127.0.0.1.** Vite 8 на Windows слушает `127.0.0.1`, а `CORS_ORIGINS` по умолчанию содержал только `http://localhost:5173`. Регистрация из браузера получала `403 origin_not_allowed`. Добавили в dev-дефолт и `.env.example` оба origin; в production список по-прежнему задаётся явно и не содержит localhost.
- **i18next v26 переименовал `initImmediate` в `initAsync`.** Синхронная инициализация нужна тестам и первому рендеру: `initAsync: false`. Типизированные ключи работают через `CustomTypeOptions.resources`, а `t()` с динамическим кодом ошибки требует маппинга на union `TranslationKey`, иначе TypeScript справедливо ругается.
- **Дефолты zod и тип формы.** `registerInputSchema` содержит `locale.default('ru')` и `.strict()`, поэтому `z.infer` (output) требует `locale`, а `zodResolver` типизирован по input, где поле опционально. Для формы используем `z.input`-совместимый тип и подставляем локаль при отправке. Не пытаться «привести» resolver кастом.
- **`max-lines-per-function` и JSX.** Форма на 80 строк — это ошибка линтера, даже если логика вынесена. Помогает разделение на hook формы (`useLoginForm`/`useRegisterForm`), мелкие компоненты (`ResultPanel`, `LoginPrompt`) и секции dev-витрины. Не отключать правило без причины.
- **Knip видит любой экспорт.** Публичный `index.ts` фичи не должен реэкспортировать хуки и типы «на будущее»: `useLogin`, `AppMode`, `ProblemDetails` пришлось убрать из публичных интерфейсов, пока их никто не импортирует. Экспорт — это контракт.
- **Шрифты `@fontsource-variable`.** Пакет подключает все подмножества (греческий, вьетнамский, latin-ext), но браузер скачивает только совпавшие по `unicode-range` (кириллица и латиница). В `dist` лежат лишние woff2 (~100 КБ), в сеть они не уходят. Если понадобится строгость — вынести только cyrillic/latin `@font-face` в свой CSS.
- **Скриншоты 360 px.** `msedge --headless --window-size=360` на Windows клампит окно до ~492 CSS px, поэтому снимок получается обрезанным, а не мобильным. Правильно — Edge с `--remote-debugging-port` и CDP `Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot`. Встроенный browser-инструмент требует видимого окна и в этом окружении снимки не делает; CDP работает.
- **Fixed bottom nav на full-page скриншоте.** При `captureBeyondViewport` фиксированная навигация рисуется один раз на высоте первого экрана и накладывается на контент. Перед полностраничным снимком витрины её нужно убрать из DOM (селектор `nav[aria-label].fixed`), иначе артефакт выглядит как баг вёрстки.
- **Письма в Mailpit не появились.** Регистрация отвечает `202` всегда, поэтому по ответу нельзя понять, ушло ли письмо. В `localhost:8025` было пусто; вероятно, SMTP-туннель не поднят. Для ручной проверки подтвердили email в dev-БД, но в Backlog записали проверку `SMTP_*` и логов mailer.
- **Проверка входа в браузере.** После подтверждения email вход через форму прошёл, cookie выставились, `useMe` вернул пользователя, защищённый `/profile` открылся. Это же подтверждает, что httpOnly cookie работают через Vite-прокси same-origin.
- **Single-flight refresh.** Тест с двумя параллельными 401 проверяет, что `/auth/refresh` вызывается ровно один раз. Без этого второй refresh отзывал family (грабли Сессии 3).
- **`invisible` убивает доступное имя кнопки.** В состоянии loading подпись нельзя скрывать через `visibility: hidden`: скринридер перестаёт видеть текст, и кнопка становится безымянной. `opacity-0` сохраняет имя и ширину, поверх крутится спиннер. Тест Testing Library это не ловил, потому что jsdom считает имя по скрытому тексту.
- **`defaultValues` в react-hook-form не обновляются.** Локаль, положенная в `defaultValues` при первом рендере, остаётся старой после переключения языка. Отправлять `locale` надо из текущего `useLocale()` в момент submit, а не из значений формы.
- **Refresh — это три состояния, а не boolean.** `response.ok === false` смешивал «refresh-токен недействителен» (нужен экран входа) и «API вернул 500/сеть упала» (нужен экран ошибки сессии). Разделили на `ok`/`unauthenticated`/`error`; иначе временный сбой разлогинивал пользователя и кэшировал `null` на 5 минут.
- **Один refresh на вкладку — мало.** Cookie-jar общий для вкладок, поэтому два параллельных refresh с одним токеном всё равно отзовут family. Добавили `navigator.locks.request('staynest-refresh')`; без Web Locks остаётся прежняя same-tab дедупликация. Серверный grace-период не делали — это отдельное решение для Сессии 11/17.
- **Web Locks нельзя держать внутри single-flight.** Если `locks.request` вызывать на каждый 401, а promise класть внутри callback, то параллельные запросы одной вкладки выстраиваются в очередь и делают N последовательных refresh. Правильно: module-level promise создаётся один раз, а лок оборачивает только `performRefresh`; тогда same-tab запросы делят один вызов, а разные вкладки сериализуются локом. `lib.dom` типизирует callback Web Locks как синхронный, хотя он принимает Promise; пришлось сделать узкий cast типа, а не `any`.
- **Ревью-регрессия.** Второй круг нашёл ровно эту ошибку: тест «Web Locks вызывается» был зелёным, но не проверял число refresh. Добавили тест с сериализующим mock-локом: два параллельных 401 → `refreshCalls === 1`, `request` вызван один раз.
- **Focus trap и фокус на самой панели.** Если фокус стоит на `dialog[tabindex="-1"]`, проверка `active === first` не срабатывает, и Shift+Tab уводит за модалку. Считать «внутри» только элементы из списка focusable, иначе заворачивать на первый/последний.
- **У EmptyState должен быть уровень заголовка.** На 404 и в ошибке сессии нет другого заголовка, поэтому компонент рендерил `h2` первым в документе. Добавили `titleAs`, страницы маршрута передают `h1`.

### 2026-10-19 / Сессия 3 / авторизация
- **Генерация списка паролей и экранирование.** PowerShell + `node -e` дважды экранировал `\n`, и в сгенерированный TS попала одна строка с литеральными `\\n`. Проверка «пароль из списка» молча не срабатывала. Генерировать такие файлы отдельным `.cjs`-скриптом с `join('\n')` и проверять тестом на конкретный пароль.
- **`@node-rs/argon2` вместо `argon2`.** Даёт argon2id с prebuilt-бинарниками и не требует node-gyp/lifecycle-сборки, что важно для pnpm 12 и Windows. Параметры по умолчанию совпадают с OWASP (19 МиБ, 2 итерации).
- **`light-my-request` не отдаёт `secure: false`.** Если флаг не выставлен, свойства `secure` в разобранной cookie просто нет. Проверять `toBeFalsy()`, а не `toMatchObject({secure:false})`.
- **`max-lines-per-function` ловит плагины Fastify.** Регистрация 13 маршрутов в одном плагине — это 100+ строк. Помогло разделение на `registerPublicRoutes` / `registerAccountRoutes` / `registerMeRoutes` и вынесение потоков авторизации из `createAuthService` в отдельные функции с `AuthRuntime`.
- **Ротация refresh и параллельные запросы.** Два одновременных refresh с одним токеном — это повторное использование: вторая транзакция видит `revoked_at` и отзывает family. Клиент обязан сериализовать refresh; для SPA это важно в Сессии 4.
- **Проверка активной family на каждом запросе.** Без неё logout не отзывал access-токен 15 минут. Один дополнительный индексный запрос — приемлемая цена за немедленный выход.
- **pnpm 12 сам дописал `minimumReleaseAgeExclude` для `nodemailer@10.1.7`.** После `pnpm add` изменился `pnpm-workspace.yaml`; это ожидаемо, но такие правки нужно проверять глазами и коммитить вместе с зависимостью.
- **PowerShell `Get-Content | Set-Content -Encoding utf8` уничтожает кириллицу.** PS 5.1 читает UTF-8 как ANSI (cp1251), запись обратно даёт mojibake. Замена `resendUser` → `resendEmail` испортила тестовые названия. Восстановили обратным преобразованием cp1251→UTF-8; впредь массовые замены делать через Node/`-Raw` + `[System.IO.File]` или edit-инструмент.
- **Ревью нашло четыре реальных major, которых не было видно в зелёных тестах:** жёсткий per-email лимит блокировал чужой вход; logout отзывал только предъявленный токен, а не family; revoke-all проигрывал гонку refresh; `REQUIRE_EMAIL_VERIFICATION` был мёртвым конфигом. Добавили блокировку строки `users` в refresh/logout/revoke-all, публичный resend по email, мягкий email-лимит и тест с trigger-задержкой вставки refresh.
- **`.env.example` — не место для рабочего секрета.** Значение `JWT_SECRET` из шаблона проходило production-проверку; теперь шаблон пустой, production отвергает `dev-only-*`, `deploy.sh` падает до сборки, если секрет не заменён.
- **Тестовая БД — общий ресурс.** Даже `fileParallelism: false` не спасает от двух одновременных `vitest`. Добавили `globalSetup` с `pg_advisory_lock` на всё время прогона; без блокировки два агента/терминала роняют друг другу схему.
- **Второй круг ревью нашёл pre-hijack и две гонки.** Регистрация чужого email с паролем атакующего + клик жертвы по ссылке активировал аккаунт с чужим паролем. Теперь `verify-email` принимает `{token,password}` и заново задаёт пароль. Login и смена пароля перепроверяют `password_hash` под `FOR UPDATE` после argon2-проверки, иначе reset мог отозвать сессии, а login успеть вставить новую. `requestPasswordReset` тоже блокирует `users`, чтобы смена пароля и запрос сброса не разъехались.
- **Тайминг-выравнивание — это не только нижняя граница.** Бюджет SMTP (400 мс) был больше floor ответа (250 мс), и существующий email отвечал дольше. Снизили бюджет письма до 200 мс при floor 250 мс; `verifyDummy` прогревается сразу, а не на первом неизвестном email.
- **Мягкий лимит не должен создавать аккаунт.** Если email-бюджет регистрации исчерпан, пользователь теперь не создаётся; иначе получался «тихий» аккаунт без письма, которым нельзя воспользоваться. Слабые пароли проверяются до лимитера, чтобы не выжигать бюджет.
- **Контракт ответа не должен врать.** `register`/`resend`/`forgot` отвечают `202 {status:"accepted"}` (регистрация ещё отдаёт `emailVerificationRequired`), потому что письмо может не уйти из-за мягкого лимита или demo-флага. `verification_sent`/`sent` убраны.


### 2026-10-19 / Сессия 2 / схема БД
- **Root-скриптам нужны свои зависимости.** В pnpm root `scripts/*.mjs` не видят `pg` из `apps/api`. Пришлось добавить `pg` и `node-pg-migrate` в devDependencies корня. `kysely-codegen` запускается через `process.execPath` + `require.resolve` (без shell), поэтому knip видит его как используемый.
- **`.mjs` — не TypeScript.** ESLint не применяет к ним блок с `globals.node` для `*.ts`, поэтому `process` и `URL` падали с `no-undef`. Добавлен блок `**/*.{cjs,mjs}`.
- **node-pg-migrate 9 грузит ESM-миграции через jiti.** Обычные `.js` с `export const up/down` работают без ts-node и без сборки.
- **kysely-codegen видит служебную таблицу.** `pgmigrations` попадает в типы, если не передать `--exclude-pattern pgmigrations`.
- **Сгенерированные типы ломают линтеры.** Файл на 277 строк близок к лимиту `max-lines` и не должен правиться вручную; исключён из ESLint и Prettier (ADR-028).
- **`pg` парсит DATE в `Date`.** По умолчанию `'2026-07-10'::date` превращается в `2026-07-09T21:00:00.000Z` (UTC+3) и при сериализации даёт предыдущий день. В пуле задан парсер OID 1082, возвращающий строку; `kysely-codegen` запускается с `--date-parser string`. Тест ловит регрессию через Kysely.
- **`pnpm audit` падает на dev-зависимости.** `kysely-codegen` тянет `braces@3.0.3` с advisory без патча (stack exhaustion на глубоких glob-паттернах). Риск ограничен локальным CLI на доверенных именах таблиц; advisory явно проигнорирован в CI с обоснованием (ADR-030), пересмотреть при обновлении codegen.
- **`DROP SCHEMA public CASCADE` удаляет и расширения.** `btree_gist`, `citext`, `pg_trgm` приходится создавать заново — это делает первая миграция, поэтому `db:reset` корректен.
- **Windows и `spawn`.** `spawnSync('pnpm', ..., { shell: true })` даёт DeprecationWarning и риск инъекции; правильнее `pnpm.cmd` без shell.
- **Тестовая база одна на все файлы.** Между тестами нужен `TRUNCATE ... RESTART IDENTITY CASCADE`, а файлы запускаются последовательно (ADR-029).

### 2026-10-19 / деплой стенда
- **Первый push в новый репозиторий ломает gitleaks-action.** Push event передаёт `before`, которого нет в истории; action строит диапазон `before^..HEAD` и падает с «unknown revision». Следующие push проходят. Не считать это утечкой; при повторении — `fetch-depth: 0` уже стоит, лечится перезапуском job.
- **Проверка портов с машины разработчика врёт.** Локальный VPN/прокси принимает TCP-соединения на любой порт, поэтому `Test-NetConnection` показывает «open» даже для 12345. Проверять через `ss -tulpn` на сервере и `/dev/tcp` с самого сервера, а не с ноутбука.
- **Docker-сборка на 1 vCPU реальна.** Два образа (api + web) собрались примерно за 2 минуты с cache-mount для pnpm store; без swap и кэша было бы заметно дольше. Кэш `/root/.local/share/pnpm/store` переживает пересборки.
- **Git в чужом каталоге.** Root не может читать репозиторий, принадлежащий `deploy`: Git ругается «dubious ownership». Все git-операции выполнять через `sudo -u deploy -H`, а не добавлять `safe.directory` root-у.
- **Deploy key вместо токена.** Приватный репозиторий на сервере читается read-only deploy key; push с сервера невозможен, токен с правом записи там не нужен.

- **SSH: порядок Include важнее номера файла.** В `sshd_config` первый полученный параметр побеждает, поэтому override нужно называть `00-staynest.conf`, а не `99-...`, иначе `40-hosting.conf` оставит `PasswordAuthentication yes`.
- **UFW хранит правила хостинг-панели.** После очистки сервера в UFW остались порты ISPmanager (21, 25, 53, 110, 143, 993, 995, 1500–1501). `ufw reset` с последующим добавлением только 22/80/443 убирает лишнее.

- **`pnpm audit` на старте чист.** После установки зависимостей известных уязвимостей уровня high нет.
- **Fastify-плагин инкапсулирует `setErrorHandler`.** Обработчик, зарегистрированный внутри плагина, не действует на маршруты соседних модулей: клиент получает дефолтный ответ Fastify с `error.message` (риск утечки DSN/SQL/PII). Обработчики 4xx/5xx и 404 нужно ставить на корневом инстансе в `app.ts`. Регрессия закрыта тестами на 500, битый JSON, 413 и доменный `AppError`.

- **Production-конфиг должен падать быстро.** В `NODE_ENV=production` без `DATABASE_URL` и `CORS_ORIGINS` API теперь не стартует, а не подхватывает dev-значения по умолчанию.
- **Node 24 умеет читать `.env` сам.** `process.loadEnvFile()` заменил зависимость `dotenv`; меньше пакетов в цепочке поставок.
- **`trustProxy` вынесен в env.** По умолчанию `false`; в проде включается только когда API доступен исключительно через Caddy.
- **GitHub Actions на Node 20 больше не запускаются.** К сентябрю 2026 Node 20 удалён с hosted runners, поэтому `checkout@v4`, `setup-node@v4`, `pnpm/action-setup@v4` и `gitleaks-action@v2` заменены на `@v6`, `@v6`, `@v5` и `@v3`. Проверять теги actions перед обновлением workflow.
- **500-е нужно логировать без message, но со стеком.** Полный `err` может содержать DSN/SQL/PII, а без стека инцидент не разобрать. Логируем `name`, `code` и кадры стека без первой строки (в ней message). `AppError` со status ≥ 500 нормализуется в generic `internal_error`, чтобы доменная ошибка не обошла политику 5xx.
- **Таймауты БД — часть конфигурации.** `DB_QUERY_TIMEOUT_MS` ограничивает и health-check, и будущие запросы; менять на перф-этапе через env, а не правкой кода (ADR-026).
- **sharp 0.35 в prebuilt-сборке не декодирует HEIC.** `sharp.format.heif.input.fileSuffix` содержит только `.avif`, хотя `libheif` в сборке есть. Поэтому HEIC отклоняется с `415`, а не падает в 500; iOS обычно отдаёт JPEG при выборе через `<input accept="image/*">`. См. ADR-047.
- **Метаданные удаляются только при сборке из сырых пикселей.** `sharp().rotate().resize().webp()` по умолчанию тоже не копирует EXIF, но надёжнее один раз декодировать в raw RGBA и собрать все варианты из него: тогда GPS/ICC не зависят от опций конкретного формата и тест проверяет именно это.
- **`limitInputPixels` проверяется до полной распаковки.** Тест с 2000×2000 и лимитом 1 Мп падает быстро; не нужно генерировать гигапиксельный файл, чтобы проверить защиту от decompression bomb.
- **`aspect-ratio` не спасает, если у `<img>` `height: 100%`.** В flex-колонке intrinsic height картинки (портретные 1000×1400) распирала плитку, и сетка становилась огромной. Решение: контейнер `relative aspect-[4/3] overflow-hidden`, картинка `absolute inset-0 size-full object-cover`. Поймано визуальной проверкой, не тестами.
- **Мультипарт и глобальный `bodyLimit`.** Глобальный лимит 1 МБ остаётся для JSON, а маршруту загрузки нужен собственный `bodyLimit` (10 МБ × 10 файлов + запас) и `limits.fileSize` в `@fastify/multipart`. Иначе легитимный файл получает 413 от JSON-парсера.
- **Локальный Mailpit: TCP есть, SMTP-приветствия нет.** Порт `127.0.0.1:1025` принимает соединение, но nodemailer получает `ETIMEDOUT` на greeting, письма не появляются в UI. Ручной сценарий С6 прошёл с `REQUIRE_EMAIL_VERIFICATION=false`; проблема окружения записана в Backlog.
- **Full-page screenshot и sticky header.** При съёмке всей страницы Chromium рисует `position: sticky` шапку в середине полотна. Для документации лучше снимать viewport после `scrollIntoView`, а не `fullPage`.
- **Проверка 360 px без DevTools-эмуляции.** Если окно браузера не ресайзится, можно открыть страницу в iframe шириной 360 px с того же origin: медиазапросы срабатывают по ширине iframe, cookie-сессия сохраняется. Временный файл `public/mobile-check.html` удалён после проверки.
- **`blob:` не покрывается `img-src 'self'`.** Превью загрузчика создаются через `URL.createObjectURL`, поэтому CSP должен явно разрешать `blob:` в `img-src`. В dev Vite CSP не ставит, и баг виден только в проде за Caddy; теперь `blob:` добавлен и в Caddy, и в helmet.
- **`AppError` со статусом ≥500 нормализовался в 500.** Обработчик отдавал доменные ошибки только при `status < 500`, поэтому `503 storage_unavailable` превращался в `500 internal_error`. Теперь любой `AppError` — это безопасный контракт с явным `detail`; нормализация остаётся только для неожиданных исключений.
- **Multipart: `parts` срабатывает раньше `files`.** При 11 файлах и `limits.parts = 10` приходит `FST_PARTS_LIMIT`, а не `FST_FILES_LIMIT`. Оба кода маппятся в `422 photos_per_upload_limit`; остальные `FST_*` — в `400 bad_multipart`, а не в ложное «файл слишком большой».
- **Память при загрузке важнее красоты сервиса.** Держать 10 исходников по 10 МБ и декодировать их по очереди — это сотни мегабайт. Multipart читается async iterable, слот семафора берётся до `toBuffer()`, файл сразу перекодируется и уходит в S3; в памяти остаются только метаданные и один исходник. Плюс семафор на 2 `sharp` и лимит 30 загрузок за 10 минут.

- **Веб-загрузчик наконец покрыт тестами.** `renderHook` + замоканные `preparePhoto`/`uploadPhoto` проверяют лимит, успех и ошибку; компонентный тест проверяет офлайн-блокировки. Без этого офлайн-баг (кнопки порядка оставались активными) проходил все проверки.
- **Опубликованное объявление требует минимум 3 фото не только при публикации.** Удаление фото проверяет остаток в той же транзакции (`422 photos_too_few_published`), иначе карточка в каталоге остаётся опубликованной без обязательных фото.
- **Сессия 10 / поиск по датам.**
  - **Vite может отдавать старый модуль.** После правки `api/catalog.ts` dev-сервер продолжал отдавать версию без `check_in`, хотя файл на диске был новый. `--force` + перезапуск решил проблему; если UI не видит новое поле, сначала проверить `/src/...` через `Invoke-WebRequest`, а не искать баг в коде.
  - **`EADDRINUSE` маскируется под «API недоступен».** Фоновый `tsx watch` упал, потому что порт 3100 уже занимал другой процесс. Перед запуском проверять `Get-NetTCPConnection -LocalPort 3100`; при падении смотреть не только UI, но и вывод фонового процесса.
  - **PowerShell 5.1 портит кириллицу в консоли.** `Get-Content` и `Select-String` показывают mojibake, хотя файлы в UTF-8. Для проверки текста писать в файл из Playwright/Python и читать `read`-инструментом, а не доверять консоли.
  - **Релевантность нельзя сортировать по полным строкам.** Все объявления содержали «озеро», `ts_rank_cd` совпадал со всем каталогом, и сортировка 8 МБ текста давала 300 мс HTTP. Двухэтапный top-N + join по PK дал 50 мс. Сначала измерять план, потом менять структуру запроса.
  - **План с коррелированными `NOT EXISTS` нестабилен.** После повторного `ANALYZE` тот же запрос переключался между nested loop (28 мс) и сортировкой всех совпадений (197 мс). Независимое QA-ревью воспроизвело 191–219 мс, хотя первый замер показывал 28 мс. Материализованный CTE `busy` + hash anti join даёт предсказуемые 32–44 мс SQL и 85 мс HTTP. Вывод: один «удачный» прогон не доказательство, нужно несколько и независимая проверка.
  - **Блокировки в перф-сиде должны попадать в замеряемый диапазон.** Сначала блоки стояли в промежутке слотов, а замер шёл на 30 дней вперёд, поэтому ветка `listing_blocks` не отсекала ни одной строки. Добавили отдельный сценарий `+16…+23`, который реально попадает в блоки.
  - **Функциональный индекс должен совпадать с выражением.** Запрос сравнивал `lower(city)`, а индекс был по `city`; `EXPLAIN` это показал только на 10k строк. Индекс `(lower(city), ...) WHERE status='published'` снимает проблему.
  - **Сид перф-данных: дата + bigint.** `date + bigint` в Postgres не работает; `row_number()` даёт bigint, поэтому номер слота нужно приводить к `int`. Активные брони раскладываются с шагом больше максимального срока, иначе EXCLUDE-ограничение валит загрузку.
  - **Playwright для скриншотов есть глобально в Python.** `python -c "from playwright.sync_api import sync_playwright"` работает, `channel='msedge'` использует установленный Edge. Это проще, чем бороться с видимостью встроенного браузера; `wait_until='networkidle'` с Vite HMR не завершается — ждать DOM и таймаут.
