# DECISIONS: журнал архитектурных решений

Формат: **ADR-NN. Название.** Статус, контекст, решение, последствия. Агент дописывает новые записи в конец. Статусы: принято, заменено (ссылка на новую), отклонено.

## ADR-001. Монорепо на pnpm workspaces
**Принято.** Общие типы и zod-схемы (`packages/shared`) используются фронтом и бэком, один CI. Последствие: единые версии TypeScript и линтеров.

## ADR-002. PWA как основной канал, Telegram Mini App как опциональная оболочка
**Принято.** У объявлений есть фото, ссылки для шаринга и SEO, это лучше в вебе. Логика авторизации и уведомлений скрывается за абстракцией, чтобы TMA добавлялся без переписывания (Сессия 19).

## ADR-003. Защита от двойного бронирования на уровне БД
**Принято.** `EXCLUDE USING gist (listing_id WITH =, stay_range WITH &&) WHERE (status IN ('pending','confirmed'))`. Приложение лишь преобразует ошибку `23P01` в 409. Последствие: корректность не зависит от количества инстансов API и гонок.

## ADR-004. Заявка `pending` блокирует даты
**Принято.** Иначе хозяин может подтвердить две пересекающиеся заявки. Минус: гость может "занять" даты и не получить ответ. Смягчение: TTL 24 часа и автоматическое истечение.

## ADR-005. Блокировки хозяина в отдельной таблице + блокировка строки объявления
**Принято.** Блокировки (`listing_blocks`) и брони (`bookings`) в разных таблицах, EXCLUDE не работает между таблицами. Поэтому при создании брони транзакция берёт `SELECT ... FOR UPDATE` строки объявления и проверяет блокировки. Альтернатива (одна таблица "занятости") отклонена: разные жизненные циклы и поля.

## ADR-006. Деньги как целые в минимальных единицах
**Принято.** `bigint` + `currency char(3)`. Расчёт только на сервере, снимок разбивки в `bookings.price_breakdown`.

## ADR-007. Модель дат `[)` и тип `date`
**Принято.** День выезда свободен для следующего заезда. Нет таймзон в датах проживания, только в сроках (`timestamptz`).

## ADR-008. Фоновые задачи на pg-boss
**Принято.** Очередь на Postgres, без Redis. Меньше инфраструктуры на одном VPS, транзакционная целостность с данными.

## ADR-009. SQL-first миграции (node-pg-migrate) + Kysely
**Принято.** Ограничения вроде EXCLUDE, partial indexes, generated columns выражаются нативным SQL, ORM их не покрывает. Kysely даёт типобезопасные запросы без скрытой магии.

## ADR-010. Авторизация: httpOnly cookie, короткий access и ротируемый refresh
**Принято.** Токены не доступны JS (защита от XSS-кражи). От CSRF: SameSite=Lax, проверка Origin, отсутствие небезопасных GET. Для Telegram Mini App возможен bearer-режим (Сессия 19).

## ADR-011. Обработка фото на сервере (sharp), хранение в MinIO, раздача через Caddy
**Принято.** Клиент сжимает для экономии трафика, сервер всё равно перекодирует (нельзя доверять клиенту), снимает EXIF, делает три WebP-варианта. В БД только префикс ключа.

## ADR-012. Курсорная пагинация
**Принято.** Стабильна при добавлении данных, не деградирует на больших смещениях. Курсор кодирует кортеж сортировки и `id`.

## ADR-013. Один аккаунт, два режима
**Принято.** Нет столбца `role`. Режим интерфейса хранится на клиенте, права выводятся из владения объектами.

## ADR-014. Поиск: tsvector (russian) + триграммы по городу
**Принято.** Достаточно для MVP без внешнего поискового движка.

## ADR-015. Платежи: только заглушка, данные карт не храним никогда
**Принято.** Реальный провайдер подключается через hosted-страницу или токенизацию; у нас только `external_id` и статус. См. Сессию 18.

## ADR-016. Уведомления: внутренние + SSE + Web Push
**Принято.** Единая точка отправки (сервис уведомлений). Push запрашивается только по действию пользователя.

## ADR-017. Модульный монолит с жёсткими границами
**Принято.** Бэкенд разбит на модули (`modules/*`), фронтенд на фичи (`features/*`); модуль общается с другими только через `index.ts` и события; границы проверяются ESLint и dependency-cruiser. Исключение: read-модели `catalog` и `dashboard` делают SQL-соединения по чужим таблицам только на чтение. Микросервисы отклонены как преждевременная сложность. Детали в `ARCHITECTURE.md`.

## ADR-018. Внутренний event bus для связи модулей
**Принято.** `bookings` публикует события `booking.*`, `notifications` подписан. События публикуются после коммита транзакции; критичные дублируются в очередь pg-boss для повторов. Минус: чуть сложнее отладка, плюс: нет циклических зависимостей.

## ADR-019. Подтверждение email обязательно для публикации и бронирования
**Принято.** Токены одноразовые, в БД хэш, срок жизни ограничен. Флаг `REQUIRE_EMAIL_VERIFICATION` позволяет отключить требование в демо-окружении. Уменьшает массовую регистрацию ботов и спам заявками.

## ADR-020. Защита от перечисления пользователей и перебора без жёсткой блокировки аккаунта
**Принято.** Единые ответы в регистрации, входе и сбросе; rate limit по IP и по email; прогрессивная задержка вместо блокировки (блокировка позволяет злоумышленнику вывести из строя чужой аккаунт).

## ADR-021. S3-хранилище: форк Silo вместо образов MinIO
**Принято.** В сентябре 2026 MinIO удалил образы `minio/minio` из Docker Hub, а `quay.io/minio/minio` перестал отдавать их анонимно (401). Стек требует S3-совместимое хранилище. Используем `pgsty/silo` — поддерживаемый сообществом форк MinIO с тем же S3 API, консолью и `mcli`; образ фиксируется по digest. Приложение работает через стандартный S3-клиент, поэтому замена хранилища не затрагивает код. ADR-011 (обработка фото, WebP, MinIO как хранилище) остаётся в силе: меняется только поставщик образа. Последствие: нужно следить за обновлениями форка; в проде фиксируется конкретный digest.

## ADR-022. Порты локальной разработки: API 3100, Postgres 5433
**Принято.** На машине разработчика порты 3000 и 5432 уже заняты другими проектами. Dev-окружение использует API `3100`, Postgres на хосте `5433` (внутри контейнера остаётся 5432), Vite проксирует `/api` на 3100. В проде порты наружу не публикуются, поэтому на деплой это не влияет.

## ADR-023. Версии инструментов: pnpm 12, TypeScript 5.9, ESLint 9
**Принято.** TypeScript 7 ещё не поддержан `typescript-eslint` (peer `<6.1.0`), ESLint 10 — не поддержан `eslint-plugin-jsx-a11y` 6.10 (peer `<=9`). Фиксируем TypeScript `~5.9.3`, ESLint `~9.39.5`, `@eslint/js` `~9.39.5`. pnpm 12 блокирует lifecycle-скрипты зависимостей: разрешения задаются в `pnpm-workspace.yaml` ключом `allowBuilds` в виде mapping (`esbuild: true`), а не списком. Пересмотреть версии, когда плагины добавят поддержку.

## ADR-024. Tailwind CSS v4 с CSS-first токенами
**Принято.** Используем Tailwind v4 и `@tailwindcss/vite`. Токены дизайн-системы объявляются в `apps/web/src/styles.css` через `@theme` (цвета, шрифты), а не в `tailwind.config.js`. Сессия 4 расширяет набор до полного `docs/DESIGN.md`. Последствие: конфигурация темы живёт в CSS, магические значения по-прежнему запрещены.

## ADR-025. Сборка API через tsup, общий пакет как TS-исходники
**Принято.** `packages/shared` экспортирует `src/index.ts`; API в разработке запускается через `tsx`, а для прода собирается `tsup` с `noExternal: ['@staynest/shared']`. Это убирает порядок сборки пакетов и отдельные `dist` для shared. Минус: пакет нельзя опубликовать как JS-библиотеку без сборки; для монорепо это не требуется.

## ADR-026. Таймаут запросов к БД через переменную окружения
**Принято.** `DB_QUERY_TIMEOUT_MS` (по умолчанию 5000) задаёт `query_timeout` и `statement_timeout` пула pg. Health-check не может висеть бесконечно, а будущие запросы каталога и бронирования ограничены сверху. На перф-данных (Сессия 10) значение поднимается через env без изменения кода. `statement_timeout` дополнительно страхует Postgres от забытых лимитов в ручных запросах.
