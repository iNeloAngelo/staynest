# Модуль listings

## Зачем

Владелец таблиц `listings` и `listing_amenities`. Хозяин создаёт черновик,
заполняет его, выбирает удобства, публикует и архивирует объявление. Публичный
каталог появится в Сессии 8 отдельным read-модулем `catalog`.

## Публичный API

Регистрирует маршруты под `/api/v1`:

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/amenities` | справочник удобств (публичный, кэш 5 минут) |
| `GET` | `/me/listings` | объявления текущего хозяина со статусами и числом заявок |
| `POST` | `/listings` | создать пустой черновик |
| `PATCH` | `/listings/:id` | обновить поля черновика или объявления |
| `PUT` | `/listings/:id/amenities` | заменить набор удобств |
| `POST` | `/listings/:id/publish` | опубликовать после проверки полноты |
| `POST` | `/listings/:id/archive` | архивировать опубликованное |
| `DELETE` | `/listings/:id` | удалить черновик |

Правила:

- все операции, кроме `GET /amenities`, требуют авторизации;
- чужое объявление всегда даёт `404 listing_not_found` — существование не
  раскрывается;
- публикация дополнительно требует подтверждённый email при
  `REQUIRE_EMAIL_VERIFICATION=true`;
- публикация проверяет название, описание от 50 символов, город, адрес,
  вместимость, цену и минимум 3 фото, возвращая `422 listing_incomplete` со
  списком `errors[]`;
- архивирование запрещено при будущих активных бронях (FR-L6);
- удалять можно только `draft`.

## Таблицы

`listings`, `listing_amenities`. Модуль только читает `listing_photos` (число
фото для публикации) и `bookings` (число заявок и запрет архива) — это
read-only проверки, запись в чужие таблицы остаётся у `photos` и `bookings`.

## События

Публикует `listing.published` после успешной публикации. Событие пока никто не
слушает — задел для Сессий 8 и 13.

## Схема и черновики

Миграция `0007_listing_drafts` разрешает незаполненные поля у `draft` и
добавляет CHECK `listings_complete_when_not_draft`: всё, что не черновик, обязано
быть полным. Черновик создаётся пустым, чтобы мастер Сессии 7 мог сохранять
шаги по одному.
