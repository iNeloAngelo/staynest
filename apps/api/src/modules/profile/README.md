# Модуль profile

## Зачем

Фото профиля: загрузка аватара, замена и удаление. Текстовые поля профиля
(`display_name`, `phone`, `locale`) по-прежнему обновляет `auth` через
`PATCH /me`; таблицей `users` владеет модуль `users`, поэтому аватар пишется
через его публичный `setAvatarKey`.

## Публичный API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/me/avatar` | multipart-поле `avatar`, квадратный WebP 512 px |
| `DELETE` | `/me/avatar` | удаляет ключ из БД и объект из хранилища |

Формат определяется по содержимому (`file-type`): JPEG, PNG, WebP, AVIF.
Ограничения — 5 МБ и `PHOTO_MAX_PIXELS`, не больше 20 загрузок в час на
пользователя. Файл перекодируется из пикселей, поэтому EXIF (включая GPS) и
прочие метаданные не сохраняются. Ключ — `avatars/<user_id>/<uuid>.webp`,
публичная политика бакета и Caddy разрешают только `avatars/*/*.webp`.

## Конфигурация

Отдельных переменных нет: используются `PHOTO_MAX_PIXELS`, `S3_*` и
`MEDIA_PUBLIC_PATH`. Публичная политика бакета ставится при старте API
(`platform/storage`).

## Как тестировать

```bash
pnpm --filter @staynest/api test
```

`apps/api/tests/profile.test.ts` проверяет загрузку, замену с удалением старого
файла, отказ поддельному файлу, отсутствие поля, удаление, `PATCH /me` и 401.
