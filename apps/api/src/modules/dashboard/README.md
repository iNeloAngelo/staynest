# Модуль dashboard

## Зачем

Read-модель панели хозяина. Один запрос отдаёт цифры для сводки: активные
заявки, ближайшие подтверждённые заезды, занятость 30 дней и доход
подтверждённых/завершённых броней по месяцам. Модуль ничего не пишет и
соединяет `listings`, `bookings`, `listing_blocks` и `users` только на чтение —
это разрешённое исключение ADR-017.

## Публичный API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/me/dashboard?months=6` | сводка по объявлениям текущего хозяина |

`months` — 1–12, по умолчанию 6. «Сегодня» считается в `LISTING_TIME_ZONE`,
окно занятости — `[сегодня, сегодня+30)`. `pendingRequests` не учитывает
просроченные заявки, даже если джоб истечения ещё не отработал. Занятость
складывается из ночей подтверждённых броней и блокировок хозяина; `pending`
показаны отдельным счётчиком. Доход группируется по месяцу заезда
(`check_in`), а не по дате создания брони.

Контракты — `packages/shared/src/dashboard.ts`.

## Таблицы

Только чтение: `bookings`, `listings`, `listing_blocks`, `users`. Запись
отсутствует.

## Как тестировать

```bash
pnpm --filter @staynest/api test
```

`apps/api/tests/dashboard.test.ts` проверяет цифры на фиксированных данных:
заявки, просроченная заявка, подтверждённый заезд, блокировка, доход по
месяцам и изоляцию от чужого хозяина.
