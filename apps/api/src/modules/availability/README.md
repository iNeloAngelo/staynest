# Модуль availability

## Зачем

Календарь занятости и блокировки дат хозяином. Публичный календарь отдаёт
только ночи и их вид (`booked`/`blocked`), без гостя, брони и причины —
аноним не должен узнать, кто и почему занял даты.

## Публичный API

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| `GET` | `/listings/:id/calendar?from&to` | публичный | занятые и заблокированные ночи |
| `GET` | `/listings/:id/calendar/host?from&to` | хозяин | брони с гостем и блокировки |
| `GET` | `/listings/:id/blocks` | хозяин | список блокировок |
| `POST` | `/listings/:id/blocks` | хозяин | заблокировать даты |
| `DELETE` | `/listings/:id/blocks/:blockId` | хозяин | снять блокировку |

## Семантика дат

- Бронь хранится как `[check_in, check_out)`: выезд не занимает ночь.
- В API блокировка задаётся **включительно**: `dateFrom` — первая ночь,
  `dateTo` — последняя ночь. В БД она лежит как `[dateFrom, dateTo + 1)`.
- Поэтому в `BlockDto` и в ответе host-календаря `dateTo` — последняя ночь,
  а `checkOut` брони — уже свободное утро.

## Проверки

- Публичный календарь и quote не видят черновик и архив (`404`).
- `from < to`, не больше 400 дней за запрос, иначе `422`.
- Блокировка в прошлом — `422 block_in_past`.
- Пересечение с активной бронью — `409 block_overlaps_booking`.
- Пересечение с другой блокировкой — `409 block_overlaps` (плюс страховка
  EXCLUDE-ограничением `listing_blocks_no_overlap`).
- Блокировка строки объявления (`FOR UPDATE`) сериализует создание блока
  с созданием брони в Сессии 11.

## Индексы

Публичный календарь использует `bookings_listing_status_idx` и GIST-индекс
EXCLUDE для `listing_blocks`. Замеры и оптимизация — Сессия 10.
