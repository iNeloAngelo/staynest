# Фича notifications

## Зачем

Колокольчик в шапке (счётчик, список, переход к брони) и переключатель Web Push
в профиле. Данные — `GET /me/notifications`, живое обновление — SSE
`GET /me/events`.

## Что внутри

- `api/notifications.ts`, `api/hooks.ts` — запросы и ключи TanStack Query.
- `model/useNotificationStream.ts` — SSE через `api.stream` с refresh при 401 и
  экспоненциальным переподключением. На событие обновляет кэш уведомлений,
  инвалидирует брони/календарь и показывает toast (`role="status"`).
- `model/labels.ts` — иконка, ключ заголовка и описание с параметрами; даты
  форматируются один раз, семантика типа остаётся на клиенте.
- `model/usePushToggle.ts` — состояние `unsupported | unavailable | configError |
  denied | off | on | busy`, разрешение браузера запрашивается только по клику.
- `model/usePushOwnerGuard.ts` — если в браузере осталась подписка другого
  аккаунта (сессия истекла без явного выхода), при входе нового пользователя
  она отписывается; владелец хранится в `staynest:push-owner`.
- `components/NotificationBell.tsx` — кнопка + `Modal`; badge `aria-hidden`,
  число входит в доступное имя кнопки, открытие отражено в `aria-expanded`.
- `components/PushToggle.tsx` — включение/выключение на текущем устройстве,
  подсказка про iPhone и отказ в разрешении; при ошибке загрузки конфигурации
  показывается `configError`, а не ложное «push не настроен».

## Service worker

`apps/web/public/sw.js` — минимальный push-only worker: `push` и
`notificationclick`. Он не кэширует запросы; полноценный Workbox появится в
Сессии 15, тогда этот файл заменится. Регистрация происходит только при клике
«Включить push», не на старте приложения.

## Ограничения

- SSE-подключение живёт в памяти вкладки; после выхода из аккаунта поток
  закрывается вместе с компонентом, а push-подписка отписывается best-effort.
- Если сервер не настроил VAPID, профиль честно показывает «Push временно
  недоступен».
