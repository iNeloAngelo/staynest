# Фича photo-uploader (web)

## Зачем

Загрузка фотографий объявления из редактора: выбор нескольких файлов или
камера, клиентское сжатие, прогресс, превью, порядок, обложка и удаление.

## Структура

```
features/photo-uploader/
├─ api/photos.ts              upload / order / cover / delete
├─ model/compress.ts          сжатие до 2000 px через canvas
├─ model/usePhotoUploads.ts   очередь загрузки и прогресс
├─ model/usePhotoOrder.ts     оптимистичный порядок и drag-and-drop
├─ model/usePhotoActions.ts   мутации порядка, обложки, удаления
├─ model/errors.ts            коды problem+json → i18n-ключи
├─ components/                PhotoUploader, PhotoGrid, PhotoTile, DropZone, Queue
└─ index.ts                   публичный интерфейс
```

## Поведение

- Исходник больше 10 МБ или не изображение отклоняется до отправки с понятным
  сообщением. Файл сжимается в WebP (fallback JPEG) до 2000 px по длинной
  стороне; сервер всё равно перекодирует его заново.
- Загрузка по одному файлу через XHR (`api.upload`), чтобы показывать прогресс
  каждого файла. При `401` клиент один раз обновляет сессию через общий
  single-flight refresh и повторяет отправку.
- Порядок меняется перетаскиванием и кнопками «раньше/позже» (клавиатура и
  тач). Изменение optimistic: при ошибке список возвращается к серверному.
- Первое фото становится обложкой автоматически; выбранная обложка помечена
  бейджем. Удаление — только через подтверждение в модалке.
- Состояния: пусто, загрузка (прогресс по файлу), ошибка с повтором, офлайн —
  все действия заблокированы с пояснением. Все строки через i18n.

## Тестирование

`model/compress.test.ts` проверяет расчёт размеров. Сетка и очередь проверены
руками на 360/768/1280 px; API-сценарии — в `tests/photos.test.ts`.
