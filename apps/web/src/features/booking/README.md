# Feature booking (гость и хозяин)

Календарь доступности, расчёт стоимости и полный жизненный цикл заявки:
создание, списки, детали, подтверждение, отклонение и отмена.

- `api/booking.ts` — `/calendar` и `/quote` для карточки дома.
- `api/bookings.ts` — `POST /bookings` с `Idempotency-Key`, список `/me/bookings`,
  деталь `/bookings/:id`, действия `confirm`/`decline`/`cancel`.
- `api/bookings-hooks.ts` — TanStack Query: бесконечный список, деталь, мутации
  и инвалидация `bookings`/`booking`/`host-calendar`.
- `model/selection.ts` — чистая логика выбора диапазона: занятую ночь нельзя
  перепрыгнуть, выезд в день занятой ночи разрешён, min/max nights проверяются
  до запроса quote.
- `model/status.ts` — метаданные статусов (иконка, тон, i18n-ключ), вкладки
  гостя и хозяина и правила показа действий. Единственный источник правды для
  цвета/подписи статуса.
- `model/useBookingRequest.ts` — отправка заявки: вход через `next`, ключ
  идемпотентности по нормализованному телу, обработка `409` с refetch календаря
  и quote.
- `components/BookingPanel.tsx` — диапазон, гости, сообщение, серверный расчёт
  и кнопка «Отправить заявку». На мобильном открывается в BottomSheet.
- `components/TripsView.tsx` — «Мои поездки»: вкладки «Предстоящие», «Прошлые»,
  «Отменённые», карточки и отмена.
- `components/HostRequestsView.tsx` — «Входящие заявки»: «Новые»,
  «Подтверждённые», «Завершённые», «Закрытые», действия хозяина.
- `components/BookingDetailView.tsx` — снимок цены, сообщения, контакты после
  подтверждения и таймлайн `booking_events`.

Сумма всегда берётся из ответа `/quote` или из `priceBreakdown` брони; клиент
не складывает цены сам. Статусы группируются на клиенте, потому что API
принимает один `status` за запрос. Контакты и точный адрес приходят только для
`confirmed`/`completed`; остальным участникам доступен только город.
