# Фича listing-editor (web)

## Зачем

Мастер создания и правки объявления из пяти шагов: основное, расположение,
характеристики и удобства, фото, цены и правила. Мастер живёт отдельно от
`features/listings`, потому что это самостоятельный сценарий с навигацией,
автосохранением и восстановлением черновика, а не просто форма.

## Структура

```
features/listing-editor/
├─ components/
│  ├─ ListingWizard.tsx       шапка, прогресс, шаги, ошибки, подтверждения
│  ├─ WizardFooter.tsx        липкая панель «Назад / Сохранить / Далее»
│  ├─ WizardNotices.tsx       офлайн, восстановление, конфликт, ошибки сохранения
│  ├─ StepPanel.tsx           содержимое текущего шага
│  ├─ ListingPreview.tsx      карточка «как увидят гости»
│  └─ *Sections.tsx           поля формы по смыслу
├─ model/
│  ├─ form.ts                 форма ↔ UpdateListingInput, рубли ↔ копейки
│  ├─ steps.ts                шаги, их поля и проверки полноты
│  ├─ draftStorage.ts         снимок несохранённого черновика в localStorage
│  ├─ wizardState.ts          выбор начального шага, восстановление и конфликт
│  ├─ wizardSave.ts           сериализованное сохранение PATCH + PUT amenities
│  ├─ useWizard*.ts           состояние формы, шагов, ошибок и действий
│  └─ *.test.ts               юнит-тесты шагов, снимка и начального состояния
└─ index.ts                   публичный интерфейс (ListingWizard)
```

## Автосохранение и восстановление

- Черновик сохраняется через 900 мс после последнего изменения (`PATCH`, затем
  `PUT /amenities`, если менялись удобства). Запросы сериализуются, чтобы
  автопубликация не обогнала сохранение.
- Каждое изменение сразу пишется в `localStorage` вместе с шагом и временем
  серверной версии. Закрытие вкладки не теряет ввод, даже если debounce не успел
  отправить запрос.
- При открытии незаконченного черновика мастер начинает с первого неполного
  шага. Если есть несохранённый снимок, он восстанавливается.
- Если сервер успел измениться после снимка, показывается конфликт: оставить
  серверную версию или вернуть свои правки. Пока конфликт не разрешён, поля
  заблокированы, чтобы новые правки не потерялись.
- У опубликованного и архивного объявления автосохранения нет: изменения уходят
  по кнопке «Сохранить». Но несохранённый снимок тоже пишется в `localStorage`
  и восстанавливается при открытии, поэтому закрытие вкладки не теряет правки,
  а индикатор честно показывает «Есть несохранённые изменения».

## Проверки по шагам

Шаг нельзя пройти, пока его поля не готовы к публикации: название и описание,
город и адрес, вместимость, минимум три фото, цена и корректные сроки. Ошибки
показываются под полями и в сводке; ссылка из сводки переключает шаг и ставит
фокус в поле.

## Публичный интерфейс

- `ListingWizard` — мастер целиком; страница передаёт черновик и `key={id}`,
  чтобы смена объявления сбрасывала состояние.

## Тестирование

```bash
pnpm --filter @staynest/web test
```

`ListingWizard.test.tsx` проходит пять шагов до публикации, проверяет
автосохранение, восстановление снимка и конфликт. `steps.test.ts`,
`draftStorage.test.ts`, `wizardState.test.ts` покрывают чистую логику.
